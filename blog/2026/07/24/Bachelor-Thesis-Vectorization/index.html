Vectorization of Convolutional Operation with MLIR for a RISC-V Vector Processor (Bachelor Thesis)

An elaboration of my bachelor thesis project.

Published

24 July 2026

Vectorizaion, in the context of compilers and High Performance Computing, refers to the transformation of scalar instructions into Single Instruction Multiple Data (SIMD) instructions, allowing the utilization of vector processors. On a higher abstraction-level, vectorization refers to the transformation of the algorithm, i.e the nested loop structure, in order to perform parallel computation.

An example of such an algorithm is the direct convolution. It is one way to compute the convolutional operation of the convolutional neural network.

The Direct Convolution

for 0...OC
    for 0...OH
        for 0...OW
        # Initialize result
            for 0...IC 
                for 0...KH
                    for 0...KW
                    # Load data
                    # Perform computation
                    # Store data

How do we optimize the direct convolution algorithm?

Step one: Increase compute intensity.

Compute intensity can be increased by doing work in parallel. Here, we utilize the vector processing ability of the RISC-V vector extension.

Step two: Decrease memory accesses.

Memory accesses encompass the STORE and LOAD operations done while the algorithm is computing. This optimization requires the tiling concept. Tiling refers to changing the order of the output computation in order to utilize local memory. That is, the reuse of already loaded data amortizes the cost of memory instructions. This is, again, a consequence of the concrete memory setup of our hardware.

In the context of a scratchpad memory; the memory hierarchy only consists of a fast cache-like on-chip memory, the scratchpad, and the registers; and the main memory.

The direct convolution, when doing inference, refers to the six nested loops iterating through the output tensor dimensions while accessing the input tensor and the weight tensor.

Brief Explainer: Tensor Structure of the Convolutional Layer

Each convolutional layer of the CNN has a number of output channels, input channels and the spatial Height and Width dimensions. Importantly, each output needs a contribution from each input layer. Each output channel is there a feature map, as each channel will reflect a certain image property. This property is captured by the weights, which is therefore a four-dimensional weight kernel tensor.

Brief Explainer: RISC-V Vector Extension with a Scratchpad Memory

The hardware utilized is a Vicuna vector co-processor with the RISC-V Vector Extension. The memory architecture is a scratchpad memory with a uniform latency. The results has been simulated via gem5.

RVV consists of 32 registers, where LMUL = 1 has 16 elements, as the vector width is 512-bit and the element width is 32-bit.

Output Channel Vectorization: A Graphical illustration

One should note, that the order of the computation - how the dimensions of the convolutional layer tensor will be traversed doing the execution of the algorithm - is an important design choice and has great impact on the performance.

Considering the Direct Convolution algorithm presented above, one can do so along the output channels (“OC”), the spatial dimension (H,W) and the input channel dimension. Here, I refer to the type of vectorization based on what dimension is being parallelized, in other words; which dimension is the innermost.

For this project, I have chosen to vectorize along the output channel dimension of the convolutional layer tensor.

I chose to vectorize along the output channels for multiple reasons:

  • It aligns with the natural factor of the RISC-V Vector Extension (RVV) (as opposed to the spatial dimension).
  • Each output channel can be computed in parallel (as opposed to the input channel dimension).

Additional Tiling

As the vectorization does not utilize the full capacity of the 32 vector registers, there is leftover register space for reducing the memory operations.

The above graphical depiction illustrates a heuristic optimization approach:

  • First, optimize parallelization by choosing the largest possible ““LMUL””.
  • If there are enough leftover registers, use these for storing an intermediate computation.
